# Gold Rate Agent

Gold Rate Agent is a Node.js automation service that retrieves the 22-carat gold rate from [The Jewellers Association](https://thejewellersassociation.org/), compares it with the previously saved rate, and sends a Telegram notification only when the rate is new or has changed.

Each execution performs one check and then exits. A scheduler such as Windows Task Scheduler or Azure Container Apps Jobs can start it periodically.

## How it works

```text
Scheduler or container start
              |
              v
       gold-agent.js
              |
              v
 Selenium + headless Chromium
              |
              v
 Read the 22-carat gold rate
              |
              v
 Compare with saved rate
        /             \
 unchanged           changed
    log only       send Telegram message
                         |
                         v
                 save the new rate
```

The application sends a message similar to:

```text
Todays gold price is Rs. 14,000
```

## Project structure

| File | Purpose |
| --- | --- |
| `gold-agent.js` | Main application workflow and orchestration |
| `gold-scraper.js` | Uses Selenium to locate and read the gold-rate element |
| `gold-state.js` | Reads and writes the previous gold rate as JSON |
| `message-generator.js` | Formats the notification message |
| `telegram-sender.js` | Sends the message through the Telegram Bot API |
| `logger.js` | Writes timestamped messages to the console and log file |

| `Dockerfile` | Builds a Node.js and Chromium runtime image |
| `Jenkinsfile` | Installs dependencies, runs tests, and builds the image |
| `architecture/` | Generated architecture diagram and source model |
| `Notes/` | Learning and deployment notes |

## Requirements

- Node.js 24 or a compatible recent Node.js version
- npm
- Google Chrome or Chromium for local Selenium execution
- A Telegram bot and destination chat/group

Docker is recommended because the included image installs Chromium automatically.

## Configuration

Create a local `.env` file in the project root:

```env
TELEGRAM_BOT_TOKEN=your-telegram-bot-token
```

The Telegram destination chat ID is currently configured in `telegram-sender.js`. The `.env` file is ignored by Git and must not be committed.

The state-file path can optionally be changed with `STATE_FILE`:

```env
STATE_FILE=last-gold-rate.json
```

For a persistent container volume, configure it to point to a mounted location, for example:

```env
STATE_FILE=/app/data/last-gold-rate.json
```

## Run locally

Install dependencies:

```bash
npm ci
```

Run the agent:

```bash
node gold-agent.js
```

The agent will open Chromium in headless mode, retrieve the rate, optionally send a Telegram message, update the state file, and exit.

## Run the tests

```bash
npm test
```

The current test suite validates the formatted message generated by `message-generator.js`.

## Run with Docker

Build the image:

```bash
docker build -t gold-rate-agent .
```

Run it with the Telegram token supplied at runtime:

```bash
docker run --rm \
  -e TELEGRAM_BOT_TOKEN=your-telegram-bot-token \
  gold-rate-agent
```

To preserve the previous rate between disposable containers, mount a persistent directory and set `STATE_FILE` to a file inside it:

```bash
docker run --rm \
  -e TELEGRAM_BOT_TOKEN=your-telegram-bot-token \
  -e STATE_FILE=/app/data/last-gold-rate.json \
  -v gold-rate-state:/app/data \
  gold-rate-agent
```

## Jenkins pipeline

The `Jenkinsfile` currently performs three stages:

1. Installs the exact dependency tree with `npm ci`.
2. Runs `npm test`.
3. Builds the Docker image as `gold-rate-agent:jenkins`.

The pipeline does not currently deploy or schedule the image.

## Runtime files

The following files are generated or contain local configuration and are intentionally ignored by Git and Docker:

- `.env`
- `gold-agent.log`
- `last-gold-rate.json`
- `node_modules/`

## Current limitations

- The scraper depends on the website element with ID `goldrate_22ct`.
- The scraped value is not yet validated for invalid or unexpected data.
- Telegram requests do not currently have an explicit timeout or retry policy.
- Concurrent executions can read and write the state file at the same time.
- The Telegram chat ID is hardcoded in `telegram-sender.js`.
- The repository contains no infrastructure-as-code for the documented Azure deployment.
- Automated test coverage currently focuses only on message formatting.
